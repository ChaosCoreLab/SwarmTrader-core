# ADR-004: Stakeholder-grade documentation UI on GitHub Pages

Date: 2026-09-30
Cycle: 005
Status: active

## Context

The cycle-004 Pages site (ADR-003) used the Jekyll `minima` default theme. The Owner reported the documentation was not presentable to stakeholders (business angels and technical evaluators) and the ArchiMate diagram was not visible (SVG 404 from a relative path under pretty permalinks, fixed-size SVG overflowing mobile, PlantUML/Mermaid fences rendering as raw code). The PoC app also 404-ed its data fetch under the Pages sub-path base.

## Decision

1. **Drop `theme: minima`** and build a self-contained Jekyll layout system (`_layouts/`, `_includes/`, `assets/css`, `assets/js`) with a light-clean visual identity: system font stack, CSS tokens for layer colors, `#fbfcfa` surface, sticky header, mobile-first responsive grid. No external webfont, no non-allowlisted plugins.

2. **Landing page with a value frame** (Product Owner Who / Problem / Impact of solving / Impact of NOT solving) and entry cards to the PoC app, the flagship use case, the architecture overview, and the docs map. Status pills reuse the `milestone-animation.html` `pd`/`pa`/`pp` convention.

3. **Use-case page template** (`use-case.html` layout) that scales to many use cases: header with status pill, collapsible value frame, the ArchiMate diagram as the centerpiece (interactive — layer tabs, hover tooltips, click-to-cell), the derived Service Layer × Aspect matrix, preconditions/main flow/failure paths, and a technical-depth link section. Navigation driven by `_data/use_cases.yml`.

4. **Inline the ArchiMate SVG via Jekyll `{% raw %}{% include %}{% endraw %}`** from `_includes/use-cases/<uc>.svg` (generated by `gen-archimate.mjs --write-svg`). The SVG is responsive (`width="100%"`, `viewBox`, `preserveAspectRatio`) and interactive (`data-layer`/`data-type`/`data-id`/`data-cell` attributes; `use-case.js` wires tabs/hover/click). This closes the 404 permanently (no `<img src>` to mis-resolve) and satisfies Article 19 (diagrams first, viewer-controlled, no auto-advance).

5. **Mermaid rendering** via pinned CDN (`mermaid@11.4.0`, `defer`, `onerror` fallback) included only on pages with `mermaid: true` frontmatter. The fenced code remains the authoritative diagram-as-code source (frontend-checklist compliant).

6. **Embed the ENI snapshot as a JSON module** (`import ... with { type: 'json' }`) so the PoC app has no runtime fetch and no base-path dependency. Validation extracted to `src/engine/snapshotValidator.js`.

## Rationale

- A custom layout system is the only way to reach stakeholder-grade presentation within Jekyll nativo (minima is a blog theme; it cannot present diagrams-first, value-framed, use-case-templated content).
- Inlining the SVG via `{% raw %}{% include %}{% endraw %}` is the standard Jekyll pattern for partials: base-invariant, responsive, and unlocks Article-19 interactivity. An `<img>` with an absolute baseurl would render but not scale or interact.
- Embedding the snapshot eliminates the class of base-path fetch bugs and matches the Owner's requirement that the data be fixed and embedded.
- Mermaid via CDN (pinned, with fallback) is the frontend-checklist-compliant way to render the existing fenced diagrams without a build step or plugin.

## Consequences

**Easier:** adding a use case = `archimate/<uc>/` cells + one `use-case-<uc>.md` (frontmatter `layout: use-case`, `archimate_svg: <uc>`, `value:`) + one `_data/use_cases.yml` entry. The diagram, matrix, and nav come for free. The app is base-path-independent.

**Harder:** the site now owns its layout/CSS/JS (maintenance surface). Mermaid depends on a CDN at view time (graceful fallback to the code block). The SVG interactivity is JS-dependent (the SVG is still legible without JS, but tabs/click require it).

## Confidence

High — the layout, SVG, and data embedding are verified locally (build, tests, archimate:check). The published site is pending the next Pages deploy (browser observation per frontend-checklist).
