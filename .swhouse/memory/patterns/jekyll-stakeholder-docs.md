# Jekyll stakeholder-grade docs UI (project pattern)

## Problem

The framework's `documentation-presentation.md` contract (diagrams-first, responsive, value-frame, scalable to many use cases) must be implemented on GitHub Pages with Jekyll nativo (no non-allowlisted plugins).

## Solution

A self-contained Jekyll layout system (no theme gem):

- `_layouts/`: `default.html` (shell), `home.html` (landing), `doc.html` (architecture/decisions/operations), `use-case.html` (the flagship template with the interactive ArchiMate diagram).
- `_includes/`: `head.html`, `header.html` (sticky), `footer.html`, `use-case-nav.html` (data-driven sidebar), `mermaid.html` (pinned CDN + onerror fallback).
- `assets/css/style.css`: light-clean tokens (`--bg #fbfcfa`, layer colors as CSS custom properties), system font stack, mobile-first grid that collapses ≤768px.
- `assets/js/archimate-browser.js` + `assets/css/archimate-browser.css`: ArchiMate browser (grid + relationship overlay, hover highlight, element detail with edit link), modeled on the tr4d3rz-docs device view; `prefers-reduced-motion` respected.
- `_data/use_cases.yml`: registry driving nav + landing cards (scales to N use cases).
- `_data/docs.yml`: nav grouped by domain (mirrors MAP.md as presentation layer).
- ArchiMate browser fragment included with `{% include use-cases/<uc>.html %}` (generated by `gen-archimate.mjs`), selected by the page frontmatter `archimate_model: <uc>`. The diagram spans the full page width; the docs nav sits below it next to the prose.
- Mermaid via `mermaid@11.4.0` CDN `defer` + `onerror` fallback, included only when page frontmatter has `mermaid: true`.

## Example

SwarmTrader `docs/architecture/use-case-eni-replay.md` uses `layout: use-case`, `archimate_model: eni-replay`, and a `value:` frontmatter block. The diagram, matrix, and nav are derived; the page adds prose and technical-depth links. See ADR-004 and ADR-005.

## Wide tables and long URLs (cycle 010)

`assets/css/style.css` has `table { width: 100% }` and no scroll container, so a document with wide tables (the 8-column grid of `docs/architecture/genome-forms-review.md`) or long URLs in a reference list made the page scroll sideways at 390 px (approximate rendering: `scrollWidth` 856, then 747 after the tables alone). Fix used: a `<style>` block local to that page, right after the title:

```
.doc-content table { display: block; max-width: 100%; overflow-x: auto; }
.doc-content li, .doc-content p { overflow-wrap: anywhere; }
```

Result in the approximate rendering: no page scroll at 390 px, tables scroll inside themselves.

Why local and not in the shared CSS: the same stylesheet serves the use-case page of cycle 007, whose model walkthrough (NRC-H02) is still pending, and its look must not change under the owner's review. If more pages need it, move the two rules to the shared CSS in a cycle that also touches that page and rerun NRC-H02.

Not verified on the real Jekyll build: whether kramdown keeps the raw `<style>` block (if it strips it, the page stays readable on a wide screen only). Check on the published page (`PENDING_HUMAN`). How the approximation was done: [[approximate-jekyll-render-without-ruby]].

Before publishing a prose-heavy page, search it for the Liquid openers (double curly brace, curly-percent) and keep formulas in code blocks with single braces.

## Known limitations

- Jekyll-specific (Liquid, `_includes`); not portable to non-Jekyll sites. The universal contract lives in `software-house-ai/protocols/documentation-presentation.md`.
- Mermaid depends on a CDN at view time (graceful fallback to the code block).
- The diagram interactivity requires JS (the grid of elements stays readable without it; arrows and details do not).
- The layout/CSS/JS is a maintenance surface owned by the project.
